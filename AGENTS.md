# Snosi contributor context

Snosi builds four Debian Trixie bootc OCI products (`snow`, `snowfield`,
`floe`, `sundog`) and `/usr`-only sysexts. Firn offers these four bootc choices
only. Snowfield ships **untested** on representative Surface hardware: its
catalog inclusion gate is waived, not passed. Snow, Floe and
Sundog have VM fresh-install PASS evidence (lab runs
`bootc-only-iso-install-54wr4` and `-fjrk8`, minideb, 2026-10-24/25; the
earlier Sundog `boot:no_report` was a lab-harness race,
[#1123](https://github.com/frostyard/snosi/issues/1123)).
The Firn ISO takes the newest published Firn release (no pin). Its GRUB
menu boots the TUI (default) or firn-gui in cage, with the TUI always on
serial; that graphics stack needs about 4.5 GiB of RAM to boot
([ADR-0022](docs/adr/0022-installer-graphical-and-console-boot-entries.md)).
Native A/B and NBC build/runtime lanes were removed; see
[ADR-0018](docs/adr/0018-remove-native-ab-and-nbc-lanes.md) and
[native prototype history](docs/native-ab-prototype-history.md).

## Build and layout

`make verify` is the credential-free baseline gate and `make ci` is what
`ci.yml` runs (core ADR-0044; see [testing](docs/design/testing.md#make-gate));
Node comes from `mise install`. `just` lists targets; `just sysexts`,
`just snow`, `just snowfield`, `just sundog`, `just floe`,
`just test-install` and `just run-qemu` cover local builds and bootc tests.
The Justfile bootstraps mkosi at the commit pinned in
`.github/workflows/build.yml`. The retained
`shared/native-ab/ci/bootstrap-mkosi.sh` and `check-mkosi-pin.sh` enforce
the same pin for the installer ISO; their directory name is historical.

The root `mkosi.conf` builds base plus sysexts. Each profile resets the
inherited `Dependencies=` list before adding `base`, then includes bootc
packages, `shared/bootc-secure/mkosi.conf`, its product composition/kernel,
and `shared/outformat/image/mkosi.conf`. mkosi list-valued settings accumulate
in `Include=` order: check the resolved summary when rearranging fragments.
The himmelblau APT source is scoped to `shared/himmelblau/sandbox/` and its
sysext builds in a separate mkosi invocation with
`--sandbox-tree=shared/himmelblau/sandbox --incremental=no --cache-only=never`,
in both `just sysexts` and `build.yml` (ADR-0020). `--cache-only=never` forces
the metadata sync (mkosi 57907f58 skips it when the base cache is current) and
mkosi requires `--incremental=no` with it. `test/third-party-apt-source-scope-test.sh` rejects a
new third-party source in `mkosi.sandbox/`. `frostyard.sources` lists
`Components: main image` (core ADR-0059); no image ships a Frostyard APT
source, and `test/frostyard-apt-image-component-test.sh` enforces both.
Only the firn-installer profile may install `frostyard-firn-gui`, which
erases disks; `test/firn-gui-scope-test.sh` rejects it in every other
package list and build script. No image may enable GDM automatic or timed
login, because no image creates the user it would name;
`test/gdm-autologin-scope-test.sh` enforces this.
Snow and Snowfield ship the Debian `gnome-system-monitor` (Flathub has no
GNOME System Monitor); the pinned Logomenu System Monitor item runs it, and
the compatibility path `/usr/libexec/missioncenter-helper` (the default of
Logomenu up to 8927224) execs it. A menu item or launcher must never name a
program the image does not ship (`test/system-monitor-launcher-test.sh`).
Snow and Snowfield ship exactly one first-login trigger,
`shared/snow/tree/etc/xdg/autostart/org.frostyard.ChairLift.FirstRun.desktop`
(`Exec=/usr/bin/chairlift-first-run`), and the app list
`usr/share/snow/first-run/apps.json`; Sundog and Floe ship none, and no
build input may name `snow-first-setup` (ADR-0028; its deb is withdrawn
from APT, so a revert needs a republication first, ADR-0031).
`shared/composition/first-login.finalize` and
`test/first-login-trigger-test.sh` enforce this; base's
`/etc/profile.d/snosi-brew.sh` must stay guarded and skip root.
Snow and Snowfield ship the Snow GTK theme
(`shared/snow/tree/usr/share/themes/Snow/`, ADR-0034), whose colours are
only core's design tokens (sha256-pinned copy
`test/fixtures/frostyard-design/colors.css`). Its libadwaita layer reaches
users through `/etc/skel/.config/gtk-4.0/gtk.css` at user priority, so it may
set only colour variables, never a widget rule
(`test/snow-gtk-theme-test.py`). The default day/night wallpaper
(`usr/share/backgrounds/snow/snow-{l,d}.svg`) is generated by
`artwork/wallpaper/generate_snow_wallpaper.py` from the hero ridge geometry;
regenerate it, never hand-edit it.
No image may give the gnome-remote-desktop daemons TPM access (no `tss` group):
48.1 seals credentials in saved TPM contexts that a reboot invalidates;
`test/grd-no-tpm-access-test.sh` enforces this.
Ship a file that replaces a dpkg conffile through `ExtraTrees=`, never
`SkeletonTrees=`: dpkg prompts on the pre-existing conffile and the build
fails at EOF on mkosi's non-interactive stdin.
The image script phases are BuildScripts, PostInstallationScripts,
FinalizeScripts and PostOutputScripts. Consult
[build pipeline](docs/design/build-pipeline.md) for the detailed composition.

`/usr` is immutable, `/etc` is deployment-managed and `/var` persists.
Sysexts overlay `/usr` only: relocate package `/opt` payloads into `/usr` and
capture only tmpfiles-referenced factory `/etc` values. Shipped runtime units
must not delete `/etc` paths or self-disable: use a `/var` run-once marker;
`check-runtime-etc-guard.sh` enforces this. No tracked tree may hold a path
at or under `usr/lib/user-tmpfiles.d`: `systemd-tmpfiles --user` never reads
it; user rules go in `usr/share/user-tmpfiles.d/` (tmpfiles.d(5)). No tracked
`user-tmpfiles.d` rule may name `.config/containers`: a per-user container
policy hides `/etc/containers/policy.json`. `check-user-tmpfiles-guard.sh`
checks tracked paths and rule contents, not build output or package files
([#1265](https://github.com/frostyard/snosi/issues/1265)). Do not ship `RequiredBy=` or
`.requires/` enablement (`check-required-by-guard.sh`). Do not uphold a
condition-gated unit (`check-upholds-guard.sh`; for sysext deltas
`shared/sysext/finalize/sysext-upholds-guard.sh`).
A sysext that ships a system unit must ship `extension-release.<name>` with
`EXTENSION_RELOAD_MANAGER=1`, or `updex features enable --now` starts nothing
until a reboot (`shared/sysext/finalize/sysext-reload-manager-guard.sh`, ADR-0026).
Lodge app sysexts must declare the user `lodge` with lodge's own sysusers line,
byte for byte, and every account their units name;
`shared/sysext/finalize/sysext-lodge-accounts-guard.sh` fails the build
otherwise (ADR-0035, #1245).
`test/sysext-authoring-contract-test.sh` also rejects a sysext `mkosi.extra/`
file at a path base ships: mkosi drops it from the delta (#1111).
Base owns the host VM runtime (`qemu-system-x86`, `qemu-utils`, `ovmf`);
every sysext runs `shared/sysext/finalize/sysext-no-base-owned.sh`, which
fails a delta that ships any glob in `shared/sysext/base-owned-paths.txt`.
Incus uses its bundled `/usr/incus` qemu, not Debian's.
The Frostyard repository key must be the content of
`/usr/lib/systemd/import-pubring.pgp`: `systemd-container/forky` overwrites
the base copy, so `shared/bootc-secure/mkosi.conf` restores it. Build-time enablement
is normalized into `/usr/share/snosi/enablement-manifest.txt`; presets
recreate links on true first boot (`/etc/machine-id` is `uninitialized`).
Every remote `uses:` in `.github/workflows/` pins a 40-hex commit SHA with a
`# vX[.Y[.Z]]` comment; the dated branch-comment form is only for the
untagged repositories in the test's allow list. Every workflow has exactly
one top-level `permissions:` of `{}` or read-only grants, and every
`actions/checkout` step sets `persist-credentials: false`.
`test/workflow-pins-test.py` enforces all three and runs in `make verify`,
`validate.yml` and `nightly-compliance.yml` (core ADR-0021, #1274).

## Secure bootc and Forky systemd

**Bootc secure composition (Task 4):** all four OCI profiles include
`shared/bootc-secure/mkosi.conf`, whose isolated, low-priority Forky APT
source supplies a coherent systemd family. The secure image ships schema-1
`/usr/lib/snosi/bootc-secure.json` for Firn and protected UKI assembly.
Protected publication in `.github/workflows/build-images.yml` compares
the supplied MOK certificate and PCR public key against
`shared/native-ab/keys/mok-2026.crt` and
`shared/native-ab/keys/pcr-signing-2026.pub`; bootc-secure and Firn also
consume the public keys. External lab bootc lanes fetch them from snosi main,
so do not rename `shared/native-ab/keys/`. Private keys never enter images:
`shared/security/no-private-keys.finalize` fails any OCI, sysext or installer
ISO build that ships a build-time private key (ADR-0019); the image finalize
removes SSH host keys and ssl-cert's snakeoil pair, and the ISO postinst
removes its SSH host keys, which sshd-keygen regenerates on every boot.
`docs/bootc-secure-operations.md` governs support claims and lifecycle gates;
fixture success does not establish production Secure Boot support.
The sealed UKI command line is `rw composefs=?<digest> lockdown=integrity`
(ADR-0027), plus `splash quiet` when the rootfs ships `usr/sbin/plymouthd`
(Snow, Snowfield, Sundog; ADR-0033). `sealed_cmdline` defines both shapes;
`validate_uki` and `test/bootc-secure-artifact-test.sh` (per product)
enforce them. Never drop
`lockdown=integrity`: linux-surface does not raise lockdown under Secure Boot,
and kargs.d and mkosi `KernelCommandLine=` do not reach a Type #2 UKI.

Forky is a compatibility risk with Frostyard bootc/libostree debs, not a
package-manager guarantee. Repeat that build/root check when either the
Frostyard debs or the selected systemd family changes: build a secure OCI
profile and run `bootc --version` and `bootc container --help` inside a
build-root-only bwrap sandbox, then validate the assembled artifact.
`shared/packages/bootc/mkosi.conf` pins that pair exactly.
`test/bootc-secure-static-test.sh` checks only the selector values, that the
upstream part of the bootc package version matches
`.assembly.bootc_version` (the full Debian version does not equal that field),
and that all four profiles consume the fragment. It cannot show that
revalidation happened: do that work when either package or the systemd family
changes. See `docs/bootc-secure-assembly-compatibility.md`.
**Last repeated 2026-11-04:** bootc 1.17.3 / libostree 2026.6 (the
ostree#3681 static-delta Flatpak fix). A clean Trixie rootfs with exactly that
pair ran `bootc --version`, `bootc container --help` and the hidden
`compute-composefs-digest-from-storage --help` (help unchanged from 1.17.1),
and 1.17.1 and 1.17.3 gave the same composefs digest for one fixed tree.
`shared/packages/bootc/finalize/bootc-pair.chroot` repeats the version,
hidden-command and libostree-floor checks in every OCI build. Secure assembly
on 1.17.3 passed on all four products in main run 41939252558 (2026-11-05;
Brian accepted the post-merge revalidation, T846a); the 1.17.1 evidence (run 40370164077, lab `l6596`) is history in
`docs/bootc-secure-assembly-compatibility.md`. bootc 1.17.3 stages global UKI
addons with an update and swaps them in at finalize, so `snosi-kargs` mirrors
`apply` and `revert` into `<ESP>/loader/addons.staged`.

**Issue 517:** Forky moved `gpt-auto-root-luks` udev rules to
`90-image-dissect.rules`, which dracut 106 did not automatically include.
`shared/bootc-secure/tree/usr/lib/dracut/dracut.conf.d/35-gpt-auto-udev-rules.conf`
installs the required rule; `test/bootc-secure-artifact-test.sh` verifies it
inside the UKI. Recheck when dracut or systemd moves the rule. NvPCR definitions
and writers are masked by `shared/bootc-secure/finalize/disable-nvpcr.chroot`:
our UKIs lack the initrd NvPCR definitions and `--sign-initrd-pcrs` policy,
while signed-PCR-11 LUKS unlock remains active. Recheck mask coverage on
Forky updates. The daily sentinel `shared/download/forky-versions.json`
opens a review PR when the source version advances; `test/check-forky-systemd-test.sh`
guards its systemd consumers and four recheck obligations (the fourth,
"snosi-health systemd-cryptsetup text", rechecks the v262 texts that
`snosi-health` parses). Snow/Snowfield's
`wsdd` is the deliberate non-systemd Forky exception (absent from Trixie),
also tracked by this sentinel. Its updates require checking the Python floor,
the Trixie dependency solve, and GVfs discovery; never select `wsdd/forky`
to promote its Python dependencies.

The secure bootc CLI `snosi-kargs` writes a signed global cmdline addon to
the ESP; arguments are append-only, measured into PCR 12 and excluded from
the signed PCR-11 unlock policy. Use `docs/snosi-kargs.md` for the operator
contract. Snow and Snowfield carry the Snow Plymouth theme from
`shared/snow/tree/usr/share/plymouth/themes/snow/`. The live
`shared/snow/tree/usr/lib/systemd/system/plymouth-start.service.d/10-wait-drm.conf`
waits (bounded) for `/dev/dri/card0` and `/dev/fb0` so Plymouth does not
race DRM discovery or the fbcon handoff (real root only: the initramfs
does not carry it). The splash arguments come only from the sealed UKI
command line (ADR-0033).

## Updates and publication

On installed bootc systems, `bootc-update-stage.timer` pulls through Podman
under the strict update policy in `/usr`
(`/usr/lib/snosi/containers/bootc-policy.json`), which root dotfiles and `/etc`
drift cannot weaken, and stages without forcing a reboot. It checks the
staged digest and writes `/run/snosi/update-check` and
`/run/snosi/update-staged`; the motd, desktop notifier and
`snosi-update-status` read this state. The system
`/etc/containers/policy.json` accepts workload images and keeps the five
Frostyard scopes signed. `--pkg-diff` uses the identity-bound
`mkosi.images/base/mkosi.extra/usr/lib/snosi/staged-packages.sh` sidecar.
That shared library retains `version=` support as an API even though the
only shipped stager publishes a bootc `digest=` identity; do not remove
its version parser without a separate interface decision.
Base enables the packaged `updex-update.timer` on every image through
`mkosi.images/base/mkosi.extra/usr/lib/systemd/system-preset/05-updex.preset`.
It stages sysext revisions with updex, and a staged revision applies at the
next boot. `shared/outformat/image/finalize/updex-timer.finalize` fails the
image build when a preset enables that timer and the unit or its
enablement-manifest entry is missing; the host opt-out is
`systemctl mask updex-update.timer`. A sysext revision that needs a base
change must set `UPDEX_MIN_IMAGE_VERSION`; see
[docs/design/sysexts.md](docs/design/sysexts.md#automatic-sysext-updates-updex-update-timer).

Base ships the root collector `snosi-health` (bash and jq; ADR-0029) and its
hourly `snosi-health.timer` (`OnBootSec=3min`, idle I/O, no `Before=`, wanted
only by `timers.target`; `06-snosi-health.preset`). It writes
`/var/lib/snosi-health/problems.json` (0644: only fields of core's
`frostyard.problem/1` that pass their v1 schema, never journal text, a path,
a username or a unit instance) and `details.json` (0640 root:sudo) by atomic
rename; `snosi-health --list` prints the problems. On a failed stage
`bootc-update-stage` adds `error_class=` to update-check, never error text.
`shared/outformat/image/finalize/snosi-health-timer.finalize` guards the
preset and manifest entry like `updex-timer.finalize`. systemd-coredump comes
from the Forky family with `Storage=none` and `ProcessSizeMax=1G`
(`shared/bootc-secure/tree/usr/lib/systemd/coredump.conf.d/50-snosi.conf`);
`shared/bootc-secure/finalize/coredump.finalize` also requires `%d` and `%F`
in the core pattern (the CVE-2025-4598 fix), no `fs.suid_dumpable=1`, and
libdw and libelf. Tests: `test/snosi-health-test.sh` (fixtures validated
against a pinned copy of core's `v1.json`),
`test/snosi-health-timer-guard-test.sh`, `test/coredump-guard-test.sh`.
`ProcessSizeMax` gates only the stack text, on the captured core size;
systemd-coredump captures up to the larger of it and the storage limit, and a
host `Storage=external` override must be an `/etc/systemd/coredump.conf.d/`
drop-in that sorts after `50-snosi.conf` (ADR-0032). State no core retention
rule from `ExternalSizeMax`: it compares the stored, possibly compressed size,
and with storage on, the cores of PID 1 and journald stay.

Floe alone ships the problem-report sender: `shared/snosi-report/tree` holds
`/usr/libexec/snosi-health-report`, `snosi-health-report.timer` and the motd
line "Problem reporting is off", and only `shared/composition/floe/mkosi.conf`
adds that tree (Sundog includes `shared/floe/tree`, so the sender has its own).
Reporting is off by default and opt-in: `sudo snosi-health reporting on|off`
writes `enabled=1|0` in `/etc/snosi-health/reporting.conf` and never deletes
that file, and no image ships `/etc/snosi-health`. The daily timer posts at
most 20 reportable problems and 1 weekly count, never a `crash` report, and
`test/snosi-health-report-test.sh` enforces all of it (ADR-0030).

`.github/workflows/build.yml` publishes sysexts; `build-images.yml` publishes
signed OCI images by immutable digest before promoting `latest`. The
first-party sysexts `lodge`, `notesd`, `maild`, `porterd` and `readd` pin
attested `.deb` files; `shared/download/verify-attestations.sh` checks their
GitHub build-provenance attestation at pin time and in every `build.yml` run
([ADR-0024](docs/adr/0024-verify-attestations-of-first-party-sysext-debs.md)).
maild's `frostmail-secrets-key.service` stays out of `Upholds=` and its preset.
Published images carry `org.opencontainers.image.version` as both a config
label and a manifest annotation equal to os-release `IMAGE_VERSION`; bootc reads the
annotation.
`build-installer-iso.yml` builds and signed-index-publishes the Firn ISO to
`isos/native/v1/`. `deploy-native-installer-redirect.yml` deploys the
retained `workers/native-installer-redirect/` stable-URL Worker. ISO
publication scripts under `shared/native-ab/publish/` and the public
`shared/native-ab/keys/import-pubring.gpg` remain live despite their names.
The ISO promote job runs `shared/native-ab/publish/retention.sh --execute`
after the index and redirect verify (ADR-0036): it keeps the live
`snosi-installer_*` ISO, the two before it and anything younger than 24
hours, and deletes at most 30 objects a run; a larger backlog deletes
nothing until a maintainer dispatches with `retention_max_delete`
(`test/iso-retention-test.sh`). Every other R2 deletion is gated per exact
object by ADR-0018.

`validate.yml` runs static guards and non-root fixtures, including Firn
catalog/ISO publication, `test/no-nbc-test.sh` and
`test/retirement-plan-test.py`. `nightly-compliance.yml` repeats secretless
policy checks. Secure bootc install and update fixtures do not substitute
for live Firn install, update or rollback evidence. See
[CI/CD](docs/design/ci-cd.md) and [testing](docs/design/testing.md).

## Documentation

Keep living design and user guidance current with code. New decisions start
from `docs/adr/TEMPLATE.md`; accepted ADRs are immutable except status and
successor pointers. `docs/README.md` indexes decisions, designs, contracts,
plans and historical records. Use `.memory/README.md` for correction-log
conventions; do not record secrets. `SECURITY.md` names each artifact's own
update path: `bootc-update-stage.timer` for images (next reboot),
`updex-update.timer` for sysexts (next boot) and a new download for the ISO.
A row of core's repository baseline (ADR-0071) is done only when its whole
rule holds, not only its check; a known gap is a follow-up issue, named in
the PR's row table.
`README.md` names no kernel suite: `shared/kernel/backports/mkosi.conf`
selects it (Forky while trixie-backports kernels are uninstallable), and a
suite named in the README goes stale when that selection moves.
A snosi ADR links another repository's gate or schedule (a lab gate, a soak,
an APT withdrawal) and never states it as snosi's; when a plan changes an
accepted ADR's consequence, a new ADR amends it (ADR-0031).
