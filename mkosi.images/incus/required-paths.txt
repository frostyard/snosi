# Runtime libraries the sysext's own payload links but that cayo's base does
# NOT provide. These are declared dependencies of packages listed in
# mkosi.conf, so apt installs them -- but a sysext delta omits anything the
# BUILD BASE already has, and until #771 (2026-08-25) base transitively
# carried a whole desktop. The r1 delta built against that fat base shipped
# without them and every `incus launch --vm` on cayo failed with "Failed
# getting QEMU version": the incus deb's bundled
# /usr/incus/bin/qemu-system-x86_64 (which incusd's wrapper puts first on
# PATH) needs libepoxy.so.0 directly, libspice-server.so.1 needs libopus.so.0,
# gtk-vnc/spice-client-gtk need libgstreamer-1.0.so.0, and qemu's ui-gtk.so
# plus virt-viewer need libgtk-3.so.0. Pinning them here makes another base
# closure change a build error rather than a silently broken publish.
/usr/lib/x86_64-linux-gnu/libepoxy.so.0
/usr/lib/x86_64-linux-gnu/libopus.so.0
/usr/lib/x86_64-linux-gnu/libgstreamer-1.0.so.0
/usr/lib/x86_64-linux-gnu/libgtk-3.so.0
# GdkPixbuf's singleton cache from this base-built graphical sysext must not
# mask Snow's SVG loader registration. The shared cache finalizer also checks
# that the cache names this exact module.
/usr/lib/x86_64-linux-gnu/gdk-pixbuf-2.0/2.10.0/loaders/libpixbufloader_svg.so
/usr/lib/x86_64-linux-gnu/gdk-pixbuf-2.0/2.10.0/loaders.cache
